# План работ

Живой документ. Что сделано — в git, здесь этого нет. Здесь остаток работы,
принятые решения и то, чего в коде не видно.

## Где мы сейчас

Основной цикл замкнут. Четыре команды превращают сырую выгрузку в книгу для экономистов:

```bash
uv run mk-forge prepare "data/raw/<выгрузка>.xlsx"     # обезличить и вынуть параметры
uv run mk-forge build configs/<акция>.yaml             # собрать книгу с формулами
uv run mk-forge validate "out/рабочие/<книга>.xlsx" --config configs/<акция>.yaml  # сверить с ядром
uv run mk-forge restore "out/рабочие/<книга>.xlsx"     # вернуть настоящие номера, готовое в out/
```

Числа сходятся тремя независимыми путями: исходная книга, собранная руками; расчетное
ядро на Python; формулы книги, которую пишет генератор. Ошибок в формулах нет,
заданная эффективная скидка равна фактической на всех уровнях.

Механика умеет две вещи: один уровень на весь пул и распределение глубины, когда
скидку раздают менеджеры по одному. Во втором случае эффективная скидка акции —
результат, а не задание. Новые участники считаются как план минус текущий пул,
а если плана нет — по фактическому темпу подключения из дат договоров.

Поверх этого стоит страница «Акция» — локальная, в браузере: поля вместо yaml,
числа во время набора, три графика, книга по кнопке с вердиктами и черновиком
абзаца. Слой «задание» отделен от транспорта: страница знает про HTTP, задание
про него не знает вовсе.

## Осталось

Цель одна: работать без программиста — и не только здесь. Людей двое: владелец, он же
разработчик, и пользователь, который не программирует. Поставка по образцу Open WebUI: один образ в ghcr,
одна команда, все состояние в одном томе, сайт внутри контейнера. У каждого своя
установка на своей машине; общего сервера и входа нет. Данные попадают в том и уходят
из него только через сайт: выгрузка — загрузкой, книга — скачиванием.

Порядок: сначала образ и то, без чего он не работает, потом загрузка данных
через сайт, потом образ для пользователя, потом доверие к данным и журнал.
Оценки — время работы ассистента; ожидание сборок, прогонов CI и проверки владельца
сверху.

Этап — одна сессия. Этап закрыт, когда есть коммит, его раздел убран из плана,
а то, что выяснилось и в коде не видно, записано в решения. Забуксовавший этап
добивается в той же сессии: контекст поломки важнее чистого листа.

### 1. Один корень данных — час

Корень данных задается переменной `MK_FORGE_HOME`. Без нее корень — папка проекта,
найденная от `mkforge/__file__` вверх до `pyproject.toml`; текущая папка корнем
не считается никогда. В образе `MK_FORGE_HOME` задан всегда: код там лежит рядом
со своим `pyproject.toml`, и поиск вверх нашел бы папку с кодом, а не том. Корень
не нашелся ни так, ни так — отказ, а не догадка. От корня считаются данные, таблица
соответствия, конфиги, книги и ключ. Ключ читается из переменной или из `.env` в корне:
на маке это тот же файл, что сейчас, переносить ничего не надо; в контейнере `.env`
лежит в томе и создается при первой обработке выгрузки, как сейчас в коде.

Громкий отказ: если таблица соответствия есть, а ключа нет, `prepare` отказывает
и новый ключ не создает. Ошибки маршрутов ловятся и пишутся в стандартный вывод —
в контейнере это `docker logs`; без чисел пула, псевдонимов и тел запросов.

*Зачем:* сейчас `.env` ищется в `Path.cwd()` (`mkforge/core/anonymize.py:168`),
и запуск не из корня молча создает второй ключ — все псевдонимы разъезжаются.
Контейнер запускается не из корня никогда. У окна, которое закрыли, сбои уходят
в никуда: `logging` в проекте не используется ни разу.
*Готово, когда* запуск из любой папки дает те же псевдонимы, `doctor` печатает корень,
а без ключа при существующей таблице программа отказывает. Проверяет владелец
по своим книгам: это единственный этап, где ошибка тихая.

### 2. Сайт в контейнере, локальный режим — полтора часа

Сервер: адрес прослушивания параметром вместо зашитого `127.0.0.1`
(`page/server.py`); фиксированный порт вместо перебора десяти; в контейнере браузер
не открывается; маршрут `/api/health`; обработчик сигнала остановки — без него Python
внутри контейнера сигнал не слышит, и Docker убивает процесс через десять секунд;
прерванная сборка пишет строку в лог. Страница стартует без данных и предлагает
загрузить выгрузку: сейчас `mk-forge page` без данных отказывает, и контейнер
с `unless-stopped` падал бы по кругу. Проверка `Host` остается, но от сети не
защищает: запрос не из браузера подставит любой `Host`. Страницу от сети закрывает
только `127.0.0.1` в пробросе порта — под тестом на `compose.yaml`.

Образ: не от root, проверка здоровья, точка входа — страница; конфиги-образцы
копируются в пустой корень при первом старте, дальше их правит страница. Точка
монтирования тома создается в образе заранее и отдается пользователю контейнера:
иначе пустой именованный том достанется root, и первая же запись упадет. На маке
это не всплывет, Docker Desktop прячет права на подключенной папке; проверять
на пустом именованном томе.
`compose.yaml` для пользователя: образ из ghcr, порт `127.0.0.1:8765:8765`, именованный
том, `restart: unless-stopped`. `compose.dev.yaml` для мака: сборка из рабочего
дерева, папка проекта томом, без перезапуска — чтобы контейнер не держал порт, пока
страница запущена из исходников. Какая акция открыта — переменной, выбор на сайте
позже. README: запуск из образа и из исходников.

Кнопка «скачать книгу»: в том руками не ходят. В списке только готовые книги из `out/`,
рабочие копии на псевдонимах туда не попадают. Готовая книга пересчитывается
во временной папке и переносится в `out/` одним переименованием: сейчас `restore`
кладет книгу в `out/` до пересчета (`restore.py:132-138`), и прерванная сборка
оставила бы в списке недосчитанную книгу. Имя книги — кириллица, отдается
в кодированном виде (`filename*=UTF-8''…`), под тестом.

*Зачем:* сервер поднимают и гасят руками; блуждающий порт рождает две страницы
с разными числами; конфиги в образе стирались бы каждым обновлением.
*Готово, когда* через `compose.dev.yaml` книга по кнопке собирается, сходится
и скачивается; через `compose.yaml` пустой том открывает страницу с приглашением
загрузить выгрузку; после `down` и повторного `up` все на месте; с другой машины
в сети страница не открывается. Файл для двойного щелчка не нужен.

### 3. Загрузка выгрузки через сайт — полтора часа

Перетащил xlsx и docx — файлы легли в корень данных, `prepare` пошел заданием
с прогрессом (механика есть, `task/jobs.py`), данные перечитались; при ошибке
обработки старые данные остаются на месте. Загрузка сырым телом с отдельным лимитом,
а не multipart: `cgi` удален в Python 3.13, свой разбор границ — шестьдесят строк
ради ничего. Имя файла приводится к базовому и приходит кодированным: кириллица
в заголовке не проходит — оба под тестом. Сырая выгрузка после успешной обработки
удаляется: для возврата номеров хватает таблицы соответствия, а лежать в томе,
куда никто не заглядывает, с настоящими номерами и выручкой ей незачем.
Понадобится — загрузить заново.

*Зачем:* данные попадают в том только через сайт. Стоит до образа для пользователя:
без загрузки образ у него будет, а положить в него данные нечем.
Таблица отделений в образ не входит: у пользователя ее нет, и без нее расчет не идет.
Загрузке нужен способ ее принять — файлом или формой по отделениям из выгрузки.

*Готово, когда* от пустого тома до скачанной книги не нужна командная строка.

### 4. Образ в ghcr для пользователя — час, половина из него ожидание CI

GitHub Actions: по тегу `vX.Y.Z` — сборка под amd64 и arm64 и публикация в ghcr
с метками версии, минорной и `latest`. Обе архитектуры собираются на родных машинах
GitHub, для arm64 это ubuntu-24.04-arm: с января 2026 он есть и в приватных
репозиториях и идет в бесплатные 2000 минут, эмуляция не нужна. Хранение и трафик
образов в ghcr бесплатны и для приватных пакетов, в общую квоту пакетов они не входят.
Версия из тега попадает в пакет и видна на странице. Смоук релиза: `mk-forge doctor` внутри
собранного образа. Обновление: `pull` и `up -d`, откат — вернуть прежний тег.

Репозиторий с 2026-09-16 публичный, а настоящих значений в образе нет, так что довод
за приватный образ снят — решить в начале этапа. Ниже приватный вариант. Инструкция для пользователя: аккаунт GitHub, доступ
на чтение к пакету в ghcr, а не к репозиторию — код и конфиги ему не нужны, а пакет
выдается отдельно в его настройках после первой публикации; классический токен
с правом читать пакеты, один раз `docker login ghcr.io`, поставить Docker Desktop
с автозапуском при входе, одна команда.

Отдельно пакет не выдается, пока он наследует доступ: опубликованный из Actions пакет
связан с репозиторием и по умолчанию берет его права, а доступ к нему тогда правится
только через репозиторий. Поэтому после первой публикации в настройках пакета:
снять «Inherit access from repository» и пригласить пользователя на чтение; там же
в «Manage Actions access» добавить сам репозиторий. Пока наследование включено,
Actions получают доступ к пакету сами; после отключения он задается в этом разделе,
и без него следующий релиз, скорее всего, не опубликуется.

*Готово, когда* на машине пользователя образ скачивается, выгрузка загружается, книга
собирается и скачивается; после отключения наследования следующий тег публикуется.

### 5. Доверие к данным — по мере надобности

Когда данные загружает не программист, тихие ошибки опаснее.

- **Манифест выгрузки** в `data/anon`: имя и sha256 исходной книги и уведомления,
  откуда взята шкала и есть ли трассовые ставки, число строк, отпечаток ключа.
  Происхождение `data/anon` сейчас не записано нигде.
- **Манифест читают** `doctor`, проверка данных, шапка страницы и черновик абзаца.
  Забытое уведомление обнуляет трассовые ставки (`extract.py:88-91`), и это не ловит
  ничто; провал обязан стать громким там, куда уходит результат.
- **Свежесть данных на странице:** снимок по csv и признак, когда данные загружены.
  Перечитывание после загрузки — в этапе 3.
- **Таблица соответствия дописывается,** а не перезаписывается: более узкая выгрузка
  сегодня обрывает связь всех собранных книг с настоящими номерами.
- **Таблица отделений сверена с экономистами:** часть пар сведена по названию,
  часть вручную, и подтверждения ни одной нет.
- **Проверки прочитанного в `extract`:** параметры читаются по жестко зашитым
  координатам, вставленная строка либо роняет разбор, либо молча смещает чтение.

### 6. Акции и журнал — по мере надобности

- **Идентификатор, версия и дата акции:** два конфига носят одинаковое название
  и в книге неразличимы.
- **Имя книги с датой:** каждая сборка молча съедает предыдущую готовую книгу.
- **Журнал расчетов:** ни один отчет никуда не пишется; «что считали в сентябре
  и с какими допущениями» сейчас неотвечаемо. Пишется из `deliver` в `finally`,
  без `worst_where` — это псевдоним договора.
- **Выбор акции на странице** и создание новой из образца: конфиг зашит на старте.
- **Журнал на странице:** список акций, параметры прошлого расчета обратно в форму,
  сравнение двух расчетов рядом.
- **Очередь сборок** вместо отказа «уже идет».

Сверх названного, если дойдут руки: автосохранение черновика формы; сводка на одну
страницу для печати; отпечаток данных и версия конфига на листе «Справочник»; решить,
что делать с разделом `данные:` в конфигах — его не читает никто.

## Чему научили свои дефекты

Механика в тестах, здесь только вывод.

- **Ячейки ввода поверх данных.** Блок ввода стоял в колонке, занятой прогнозом маржи,
  и молча затирал пять месяцев; проявилось бы только при другом периоде акции. У каждого
  блока листа теперь есть проверка, что он не залезает в соседний.
- **Две нарезки пула.** Ядро округляло число договоров в срезе, книга шла по накопленной
  доле. Правило нарезки одно, и задает его книга: ядро подчиняется ей, а не наоборот.
- **Порядок зависел от подменяемого.** Срезы сортировались с участием номера договора,
  а настоящие номера подставляются последним шагом. Порядок не должен зависеть от того,
  что меняется после расчета.

## Решения, принятые по ходу

Чтобы не переоткрывать то же самое.

**Поставка по образцу Open WebUI.** Один образ в ghcr под две архитектуры, одна
команда, все состояние в одном томе, сайт внутри контейнера. Причина образа —
не изоляция, а LibreOffice: без него книга не пересчитывается и не сверяется,
а ставить его руками на каждой машине требовать нельзя. Странице самой LibreOffice
не нужен, числа считает ядро. Первое решение было «без Docker», второе — гибрид
«локально в систему, для остальных образ». Оба сняты: образ один для всех, включая
этот мак, когда нужно проверить, что получат другие.

**У каждого своя установка.** Одна у владельца, другая у пользователя. Общего
сервера нет, входа нет. Порт публикуется только на петлю хоста, и это единственный
рубеж от сети: проверка `Host` защищает от чужого сайта в браузере, но не от запроса
с подставленным заголовком. Сетевой режим со входом — другой продукт, в план
не входит. Правило о сырых выгрузках соблюдается: том лежит на машине того, кто
загрузил выгрузку. Данные между установками не ходят: у каждой свой ключ, свои
псевдонимы и своя таблица соответствия.

**Через сайт в обе стороны.** Выгрузка попадает в том только загрузкой, книга уходит
только скачиванием; руками в том не ходит никто. Нескачанное — параметры акций, журнал,
ключ — живет только в томе: удаление тома или сброс Docker Desktop стирает их,
скачанные книги остаются. Риск принят, резервного копирования нет.

**Образ приватный, контейнер перезапускается сам.** Решение принималось, когда репозиторий
был приватным, а конфиги в нем несли параметры настоящей акции. С 2026-09-16 это
не так (см. «Публичный репозиторий»), и приватность образа пересматривается на этапе 4. Цена приватности — аккаунт GitHub и один вход в ghcr на машине пользователя;
если это окажется больно, запасной путь — образ файлом через `docker save`.
Перезапуск `unless-stopped`: после перезагрузки страница есть по адресу без команд,
ручную остановку контейнер уважает. Простой стоит один спящий процесс, LibreOffice
работает только во время сборки. Старое возражение «служба требует присмотра» снято:
в фоне ничего не считается, сбои уходят в журнал контейнера.

**Две петли разработки.** На маке страница из исходников с системным LibreOffice,
образ не участвует. Проверить, что получат другие, — сборка из рабочего дерева
через compose для разработки, слой с LibreOffice кэшируется. К пользователю код
доходит только по тегу, коммиты в `main` его не трогают. Файла для двойного щелчка
не будет: его заменяет контейнер.

**Тесты при push — без LibreOffice.** CI прогоняет все, кроме помеченных `libreoffice`,
и отсеивает их пометкой, а не пропуском внутри теста: иначе состав прогона зависел бы
от того, что GitHub поставит на свою машину. Новому тесту с пересчетом нужна пометка,
без нее в CI он упадет или молча пропустится. Версии actions закреплены и сами
не обновляются: у `setup-uv` с v8 нет мажорных тегов, только точные.

**LibreOffice из Debian считает как на маке.** Проверено черновым образом 2026-09-16:
Debian 13, LibreOffice 25.2.3 из пакета `libreoffice-calc-nogui`, на маке 26.8.
Сверка сошлась: книги по всем четырем конфигам из `data/anon` без ошибок в формулах
и совпадают с ядром, тесты с пересчетом внутри образа проходят. Сборка с сайта
LibreOffice не нужна. Образ без pytest — около 885 МБ на диске и 230 МБ сжатым,
из них LibreOffice около 200 МБ. Пересчет со сверкой — 2–3 с на книгу в контейнере,
3–4 с на маке. Проверен только arm64, amd64 не собирался.

**Docker Desktop и папка «Документы».** Проект лежит в `~/Documents`, а на эту папку
macOS требует у Docker Desktop отдельного разрешения. Без него контейнер с папкой
оттуда молча висит в «Created», а за ним и все следующие, даже без папок; ошибки нет
ни в выводе, ни в `docker ps`. Доступ выдан 2026-09-16. На новом маке или после сброса
Docker Desktop это первое, что проверять, если не стартует `compose.dev.yaml`.
У пользователя том именованный, его это не касается.

**Страница — рабочая поверхность, книга — вывоз.** Поля страницы это поля конфига.
Числа считает ядро, поэтому LibreOffice ей не нужен; книга собирается по кнопке.
Страница пишет конфиг, а не книгу: собери она книгу из того, что в памяти, вышел бы
файл, который нельзя воспроизвести. Слой «задание» не знает про транспорт — чтобы
второй фасад, если понадобится, не стал вторым расчетом.

**Чего не делаем.** Телеграм-бот с хостингом, интерфейс механики с реестром
и отдельный расчет по трассовым АЗС сняты. Последний упирается не в нас: в выгрузке
нет признака трассовой АЗС, а шкала для него давно готова. CI есть, но только
для тестов и образа.

**Русский только в данных.** Имена в коде английские. Русскими остаются значения строк
(заголовки выгрузки, имена полей csv), комментарии, докстринги и вывод в терминал.

**Ядро против формул.** Книга для экономистов живая, все расчеты в формулах Excel.
Ядро на Python считает то же самое параллельно и служит контролем: `verify` сверяет
и падает при расхождении. Дублирование логики осознанное.

**Абстракции не раньше второй реализации.** Интерфейс механики и реестр не делаем,
пока есть одна акция: выводить абстракцию из одного примера — способ получить
неудобный интерфейс.

**Точность в тестах, не в отчетах.** Числа настоящей акции живут только локально:
в `reference/README.md` и в конфигах вне git. Тесты держат ту же точность на условных
числах, а контрольные доли календаря посчитаны вручную по формулам эталона.
В переписке — структура и смысл.

**Публичный репозиторий.** Открыт владельцем 2026-09-16 и опубликован одним коммитом:
полная история осталась локальной копией. В git нет названий компаний, людей,
оргструктуры и чисел настоящих акций. Вне git: настоящие конфиги рядом с примерами
в `configs/`, эталон в `reference/`, таблица отделений в `data/anon/branch_regions.csv`.
Отделения раньше были зашиты в код; теперь их ведут руками рядом с данными, и `doctor`
показывает, есть ли таблица. Остался формат: имена листов, колонок выгрузки и таблицы
уведомления, координаты чтения книги — без них выгрузку не прочитать. Коммиты
подписываются no-reply адресом GitHub.

## Дефекты эталонной книги

Найдены по ходу, воспроизводить не надо. Подробности в `reference/README.md`, он только локальный.

- Диапазоны SUMIFS по листу транзакций разъехались: часть колонок считает по всем
  строкам, часть — впритык до последней. Сейчас результат верный, зазора ноль.
- Соответствие отделений и регионов маржи существовало только внутри одной формулы.
- Транзакция без отделения разбавляет маржу месяца вниз и никак себя не проявляет.
- Один регион в прогнозе маржи есть, но ни одно отделение на него не ссылается.
