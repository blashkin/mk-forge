# mk-forge

Генератор расчетных моделей маркетинговых кампаний (МК) топливной программы в формате Excel.

## Зачем

Акции считали руками в Excel. Результаты были вбиты в ячейки, границы диапазонов
вписаны вручную и разъехались между колонками, а допущения жили в ячейках и
восстанавливались только чтением формул. К такой книге нельзя задать вопрос:
непонятно, откуда взялось число и что будет, если поменять условие.

mk-forge собирает книгу, в которой все расчеты остаются формулами Excel — она
приходит экономисту живой. Параллельно то же самое считает ядро на Python: оно
не заполняет ячейки, а служит вторым независимым путем, с которым книга
сверяется перед отправкой. Расходятся — книгу отдавать нельзя.

## Два режима

**Своя книга.** Из выгрузки транзакций и договоров, шкалы СТП из уведомления и
конфига акции собирается книга с формулами, пересчитывается и сверяется с ядром.

**Чужая книга.** Экономист присылает свой файл и просит исправить расчет. Тогда
правится его файл: форма отчета не меняется, в книгу не добавляется ничего —
ни листа, ни колонки, ни примечания. Порядок работы и три обязательные сверки
лежат в скилле `.claude/skills/patch-workbook/`.

## Страница «Акция»

```bash
uv run mk-forge page configs/<акция>.yaml
```

Локальная страница в браузере: поля вместо yaml, числа меняются во время набора,
три графика, по кнопке — книга с вердиктами и черновиком абзаца для пересылки.
Страница считает ядром, поэтому LibreOffice ей не нужен; он нужен только сборке.

Страница — рабочая поверхность, Excel остается на вывоз. Параметры она пишет
в конфиг, а книгу собирает уже из файла: источник истины один. Сервер слушает
только `127.0.0.1` и никуда не обращается — ни за шрифтами, ни за библиотеками
графиков, потому что на странице числа по реальному пулу.

## Как завести

```bash
uv sync
uv run mk-forge doctor                                     # что найдено, чего не хватает
uv run mk-forge prepare "data/raw/<выгрузка>.xlsx" \
    --notice "data/raw/<уведомление>.docx"                 # обезличить и вынуть параметры
uv run mk-forge build configs/<акция>.yaml                 # собрать книгу с формулами
uv run mk-forge validate "out/рабочие/<книга>.xlsx" \
    --config configs/<акция>.yaml                          # пересчитать и сверить с ядром
uv run mk-forge restore "out/рабочие/<книга>.xlsx"         # вернуть настоящие номера
```

Пути считаются от корня данных, а не от текущей папки. Корень — переменная
`MK_FORGE_HOME` с абсолютным путем, без нее — папка проекта; `doctor` печатает,
какой найден. Из другой папки команды запускаются через
`uv run --project <папка проекта> mk-forge …`. Ключ обезличивания берется
из `MK_FORGE_HMAC_KEY` или из `.env` в корне. Если таблица соответствия есть,
а ключа нет, `prepare` отказывает и нового ключа не создает: с новым ключом
псевдонимы не совпали бы со старыми.

Кроме выгрузки нужна таблица отделений `data/anon/branch_regions.csv`: ее ведут руками,
`prepare` ее не создает (см. `data/README.md`).

Сборка и пересчет идут в `out/рабочие/`, готовая книга ложится в `out/`. Порядок
важен: `validate` работает по псевдонимам, поэтому настоящие номера договоров
возвращаются последним шагом.

Для пересчета нужен LibreOffice: `brew install --cask libreoffice` на macOS,
`apt install libreoffice-calc` на Linux.

## Где остановились

Основной цикл замкнут: сырая выгрузка превращается в проверенную книгу. Числа
сходятся тремя независимыми путями — книга, собранная руками; ядро на Python;
формулы книги, которую пишет генератор.

Механика пока одна: надбавка к СТП. Глубина задается либо одним уровнем на весь
пул, либо распределением по долям пула, когда скидку раздают менеджеры по одному.
Новые участники считаются как план минус текущий пул, а если плана нет — по
фактическому темпу подключения из дат договоров.

Расчет перестал быть командной строкой: страница «Акция» показывает числа сразу,
а книгу собирает по кнопке. Слой «задание» отделен от транспорта, так что вторым
фасадом может встать что угодно — расчет от этого не удвоится.

Дальше — работать без программиста, и не только здесь: образ с Python и LibreOffice
внутри по образцу Open WebUI, одна команда запуска, выгрузка через саму страницу,
журнал посчитанного. Список работ с причинами — в `PLAN.md`.

Отдельного расчета по трассовым АЗС нет и не будет, пока в выгрузке нет признака
трассовой АЗС.

Решения, принятые по ходу, и чему научили свои дефекты — в `PLAN.md`.

## Где что лежит

```
mkforge/     код: ядро расчета, механики акций, сборка книги, задание, страница
configs/     условные примеры; настоящие конфиги лежат рядом и в git не попадают
data/raw/    сырые выгрузки, с машины не уходят
data/anon/   обезличенные данные, только с ними работают сессии и CI
out/         готовые книги; правка/ — правки чужих книг, рабочие/ — копии на псевдонимах
reference/   эталон первой сборки, для сверки логики, только локально
tests/       синтетический пул строится на лету, реальных данных нет
.claude/     правила проекта и скиллы
```

## Правила и данные

- `CLAUDE.md` — как устроена работа и что считается поставкой.
- `PLAN.md` — решения, принятые по ходу, и чему научили свои дефекты.
- `data/README.md` — состав выгрузки и обезличивание.

Сырые выгрузки с машины не уходят. В git не попадают ни номера договоров, ни
выручка, ни данные клиентов — ни в каком виде, включая фикстуры: тестовый пул
синтетический и строится на лету. Репозиторий публичный, поэтому в нем нет и
настоящих конфигов, отделений, шкал и чисел эталона: конфиги в `configs/` и числа
в тестах условные.
