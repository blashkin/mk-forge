# mk-forge

Генератор Excel-моделей маркетинговых кампаний (МК) топливной программы. Читай README.md.

## Правила работы

- Книга, которую получают экономисты, живая: все расчеты в формулах Excel, никаких захардкоженных результатов в ячейках. Python книгу собирает через openpyxl, а не считает за нее.
- Расчетное ядро на Python (`mkforge/core/`) считает то же самое параллельно и нужно для контроля, а не для заполнения ячеек. `validate.py` сверяет числа ядра с пересчитанной книгой и падает при расхождении. Дублирование логики между ядром и формулами осознанное.
- Источник истины для конкретной акции один: конфиг в `configs/` плюс входные данные. Excel, JSON и HTML это рендереры одного и того же результата.
- После каждой сборки прогонять пересчет в LibreOffice (soffice --headless) и проверять: ноль ошибок в формулах, эффективная скидка равна цели, суммы по сегментам сходятся с итогом.
- Формулы только из набора Excel 2007: SUMIFS, SUMPRODUCT, INDEX, MATCH, IFERROR, EOMONTH. Без XLOOKUP, FILTER, LET, динамических массивов.
- Проценты хранить долями (0.01), не числами (1).
- Сырые выгрузки лежат в `data/raw/` и не выходят за пределы машины. Наружу (облачная сессия, GitHub, CI) уезжают только `data/anon/` или синтетика. Тесты всегда на синтетическом пуле: он строится на лету в `tests/conftest.py`, реальные выгрузки в тестах не участвуют.
- Результаты сборки пишем в `out/`. Папка `build/` зарезервирована за артефактами Python-упаковки, книги туда не кладем.
- Коммиты на русском, заголовок в прошедшем времени, без Co-Authored-By и упоминаний AI.

## Поставка

- Если книгу принимает не тот, кто ставит задачу, поставка это исправленные
  числа в его же файле плюс короткий абзац для пересылки. Новая книга
  собирается только по прямой просьбе.
- В чужую книгу не добавляется ничего: ни листа, ни колонки, ни примечания.
  Что нужно объяснить — объясняется сообщением человеку, а не вписывается
  в файл.
- «Не меняй файл» сильнее «посчитай правильно». Сначала сохранить форму
  отчета, потом исправлять числа. Если без смены формы задача не решается,
  сказать это до сборки, а не показать postfactum.
- Правка чужой книги проходит три сверки: пересчет без ошибок в формулах,
  величины против ядра, структура против исходника — листы, строки,
  именованные диапазоны, проверки ввода, формулы вне правки. Файл
  в `data/raw` не меняется никогда.
- Числа конкретной акции не вписываются ни в текст книги, ни в код
  рендерера: план, границы скидок и сроки берутся из конфига.

## Предметная область

- СТП: специальная цена, скидка в процентах от розничной цены. Шкала по объему выборки клиента (тыс. л/мес), задается уведомлением. Для ДТ скидка убывает с ростом объема, АБ и СУГ 0%. На трассовых АЗС отдельная шкала. Настоящие ставки берутся из уведомления и в репозиторий не записываются.
- Сервисный сбор: процент от выручки после скидки, ставка примерно равна СТП сегмента, поэтому шкала СТП компенсирует сбор и базовая эффективная скидка близка к нулю.
- Эффективная скидка клиента = 1 - (1 - СТП - надбавка) x (1 + ставка сбора).
- Механика мотивационной акции: надбавка к СТП на ДТ, уровень задается как целевая эффективная скидка 1-5%. Номинал надбавки подбирается так, чтобы средневзвешенная эффективная скидка равнялась цели: надбавка = (цель x выручка с акцией - скидка при надбавке 0 + сбор при надбавке 0) / (выручка с акцией + снижение сбора на 1 п.п. надбавки).
- Глубина может быть не одна на пул, а распределена: доля пула получает 1%, доля — 2% и так далее. Тогда надбавка подбирается срезу, а не пулу (у крупных СТП ниже, значит на ту же глубину нужна надбавка выше), а эффективная скидка акции становится результатом. Раздача либо по объему (глубже тем, кто больше везет — консервативный случай), либо вне зависимости от размера клиента.
- Прогноз новых участников: либо план минус текущий пул, либо фактический темп подключения по датам договоров, умноженный на срок акции и на множитель ускорения. Прогнозный пул кладется в книгу строками.
- Новые клиенты подключаются равномерно по дням акции, считаются с даты подключения. Структура новых как в текущем пуле по сегментам шкалы.
- Затраты акции = скидка + OPEX + коммуникация. Окупаемость = (маржа + затраты) / затраты. ROI = маржа / затраты.
- Трассовые АЗС: надбавка не суммируется с трассовой шкалой, отдельный расчет не делается, ограничение данных фиксируется в правилах акции.

## Структура репозитория

```
mkforge/          пакет: core (ядро), campaigns (механики), renderers (книга),
                  task (задание), page (страница), cli
configs/          условные примеры; настоящие конфиги лежат рядом и в git не попадают
data/raw/         сырые выгрузки, из машины не уходят
data/anon/        обезличенные данные, только с ними работают сессии и CI
out/              собранные книги; правка/ — правки чужих книг, рабочие/ — копии на псевдонимах
reference/        эталон первой сборки: скрипты и книги, не для запуска, только локально
tests/            синтетический пул строится в conftest.py, реальных данных нет
.claude/skills/   patch-workbook: правка чужой книги на месте и три сверки к ней
```

Репозиторий публичный. В git не попадают `data/` (кроме описания), `out/`, `reference/` и настоящие конфиги — см. `.gitignore`: в них названия, оргструктура и числа настоящих акций.

## Структура книги (эталон)

Листы: Витрина акции, Расчет акции, База для расчета, База участников, Транзакции участников, Справочник, Справочник МК.
При заданном распределении глубины добавляется лист «Прогнозный пул» — после «Базы участников».
Эталонные файлы и скрипты первой сборки лежат в reference/ (не для запуска, для сверки логики, только локально).
